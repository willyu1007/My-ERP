# Roadmap — M1 总账核心 (General Ledger Core)

> 宏观规划。决策来源：`docs/project/overview/`（requirements / blueprint）。硬约束见根 `AGENTS.md`。

## 目标
落地财务模块 v1 的**总账核心闭环**：组织/账套/邀请权限底座 → 会计科目体系 → 记账凭证（借贷平衡/审核/过账/红冲）→ 期初建账 → 科目余额与试算平衡。为 M2（出纳资金）打好账务地基。

## 范围（M1 In）
- **平台底座**：monorepo 实体化（apps/api·web，packages/*）、Prisma 接入、Logto SSO、CASL 授权、Postgres RLS 基线、审计日志、OTel/结构化日志、env 契约。
- **组织与权限**：Organization / Membership / Role / Invitation（邀请制）+ RBAC + 账套（LedgerBook）+ 账套级隔离。
- **科目体系**：Account（多级、辅助核算标记、借贷方向）+ 《小企业会计准则》科目模板种子。
- **记账凭证**：JournalVoucher + JournalEntryLine；借贷平衡校验；制单/审核(SoD)/过账(事务)/红冲；附件元数据。
- **账簿**：AccountBalance（过账更新）+ 试算平衡表 + 总账/明细账查询。
- **期初建账**：启用期间 + 期初余额录入/导入（科目/往来/资金账户占位）+ 试算平衡校验。

## 非范围（M1 Out → 后续里程碑）
- 出纳资金（收付款/日记账/记账规则自动生成凭证）→ M2
- 财务报表（BS/IS/CF）→ M3；银行对账 → v1.1
- 票据 OCR → M4；My-Chat 事件/审批联动 → M5
- 多币种、合并报表、税务申报、自动划款 → OUT

## 里程碑内阶段
| 阶段 | 主题 | 退出标准（概要） |
|---|---|---|
| P0 | 平台底座 | api/web 可启动；Prisma 连库；Logto 登录通；CASL+RLS 基线；CI 绿 |
| P1 | 组织/账套/邀请/权限 | 建组织→邀请成员→授角色→建账套；账套级隔离生效 |
| P2 | 科目体系 | 小企业准则模板可初始化；科目 CRUD + 多级/辅助核算 |
| P3 | 记账凭证 | 制单(借贷平衡)→审核(SoD)→过账(事务)→红冲，全留痕 |
| P4 | 余额与账簿 | 过账更新余额；试算平衡；总账/明细账查询 |
| P5 | 期初建账 | 启用期 + 期初余额录入/导入 + 平衡校验 |

## 关键风险与对策
- **财务正确性**（借贷不平/过账不一致）→ 领域不变式 + DB 约束 + 事务 + 强测试。
- **账套越权** → 应用层作用域 + Postgres RLS 双保险 + 安全测试。
- **范围蔓延** → 严守 M1 Out；出纳/报表/OCR 入后续里程碑。
- **Logto Organizations 接入不确定** → 先用 Logto 抽象 + mock 组织，接入参数待与 My-Chat 对齐（见 overview 开放问题）。

## 回滚策略
- 每阶段独立分支 + PR；Prisma 迁移可回退（down/重建）；过账/结账为事务，失败整体回滚；种子数据幂等可重跑。

## 开放问题（带入实现）
- Logto Organizations 的邀请/成员接入参数（需与 My-Chat 团队对齐）。
- 账套与组织映射的最终粒度确认（当前：一组织可多账套）。
- 小企业准则科目模板的具体科目清单来源（标准表 vs 自定义起步集）。
